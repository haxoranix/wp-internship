Chapter 01 of 15

What Is WordPress?

Understand what WordPress really is, how it started, why it became so large, and why it should not be confused with a page builder.

Start with the big picture

WordPress is a CMS and an application platform

A CMS is a Content Management System. Instead of writing every page directly inside an HTML file, you store content in a structured system and let the website generate the right output when someone visits a URL.

WordPress started in 2003 when Matt Mullenweg and Mike Little created a fork of b2/cafelog. It grew from a blogging tool into a general-purpose web platform used for publishing, business websites, e-commerce, membership sites, directories, learning sites, portals, and custom applications.

WordPress ecosystem
WordPress Core
Theme
Plugins
Content
Database
Media
Bridge from HTML, CSS, JS

Traditional static site thinking

You create files such as index.html, style.css, and script.js. Content often lives directly inside those files.

WordPress thinking

Content can live in the database. PHP and WordPress generate HTML. Themes control presentation. Plugins extend behavior. Your CSS and JavaScript still run in the browser.

WordPress.org vs WordPress.com

WordPress.org

The open-source WordPress software. You choose hosting, install WordPress, and control code, themes, plugins, data, and deployment.

WordPress.com

A hosted service built around WordPress. Hosting and many platform decisions are managed for you, with capabilities depending on the service plan.

What can WordPress power?

Business website

Service pages, landing pages, blogs, forms, SEO controls, media, and multiple team users.

E-commerce

WooCommerce can add products, carts, checkout, orders, customer accounts, payments, and extensions.

Custom platform

Developers can build custom post types, fields, APIs, dashboards, workflows, directories, memberships, and integrations.

Common misconception

"WordPress is just drag and drop."

Page builders are only one layer. WordPress itself is the CMS and application system underneath. A developer can build custom themes, plugins, APIs, data models, admin experiences, and front-end systems without using a page builder at all.

Remember: WordPress gives you a system. It does not automatically guarantee good design, security, performance, SEO, backups, or maintenance. Those still need correct implementation.

WordPress Architecture

See how Core, themes, plugins, the database, and uploaded files work together to produce a website.

The request flow

When a visitor opens a WordPress URL, the browser does not simply download one permanent HTML file. The server runs WordPress, WordPress reads data and configuration, the active theme decides how the content should be presented, plugins can modify or extend the process, and the final HTML, CSS, and JavaScript are sent to the browser.

→

The main pieces

Core

The main WordPress software. It provides routing, admin screens, content APIs, users, media handling, hooks, and the foundation other layers use.

Theme

Controls how content is displayed through templates, layout, typography, styling, and presentation.

Plugins

Add or modify functionality such as forms, SEO, e-commerce, security, custom fields, caching, integrations, or custom business logic.

Database

Stores structured information such as posts, pages, users, settings, taxonomies, comments, and metadata.

Uploads

Images, PDFs, videos, and other uploaded files normally live in wp-content/uploads.

Content

The pages, posts, titles, text, metadata, taxonomies, and relationships WordPress manages.

Examples

Service page

The title and body are content. The theme decides the layout. An SEO plugin can add metadata. WordPress assembles the final page.

Contact form

A plugin can provide form fields, validation, submissions, email notifications, and integrations while the theme controls presentation.

Product page

WooCommerce adds products, prices, inventory, cart logic, checkout, and orders while WordPress remains the underlying platform.

Remember: Knowing which layer owns a problem is one of the most important WordPress debugging skills.

Chapter 04 of 15

Pages vs Posts

Understand the difference between permanent site content and chronological publishing content.

The simple rule

Pages

Use Pages for stable website content that is not mainly organized by publication date.

Examples: Home, About, Services, Contact, Pricing, Privacy Policy.

Posts

Use Posts for content that belongs to an ongoing publishing stream and can be organized by date, category, tag, and archive.

Examples: Blog articles, news, announcements, guides, company updates.

Comparison
AreaPagePost
Typical purposePermanent site contentPublishing content
Date importanceUsually lowUsually higher
Categories and tagsNot standard by defaultBuilt in
ArchivesNot normally part of blog archivesAppears in post archives
HierarchyCan have parent and child pagesNormally organized through taxonomies
Common mistakes

Service as a Post

A permanent service page becomes mixed into blog archives and publishing logic.

Blog as Pages

Every article becomes manually organized and you lose the normal post archive and taxonomy workflow.

Correct structure

Keep commercial or structural pages as Pages and editorial publishing as Posts.

Remember: Ask whether the content belongs to the website structure or to the publishing stream.

Categories, Tags and Taxonomies

Learn how WordPress groups content and why a planned taxonomy is better than creating labels randomly.

Taxonomy means classification

A taxonomy is a system for grouping content. WordPress includes Categories and Tags for Posts. Developers can also create custom taxonomies for custom content models.

Content taxonomy tree
Blog
WordPress
SEO
Hosting
Post A
Post B
Post C
Tags can cross topics: Performance, Security, Beginner
The pieces

Categories

Broad content groups. They can be hierarchical, so a category can have child categories.

Tags

More specific labels that can connect related posts across different categories. Tags are not hierarchical by default.

Custom taxonomy

A developer can create a classification system when the content model needs something more meaningful than Categories or Tags.

Term

A term is an individual item inside a taxonomy, such as the category "WordPress" or the tag "Security".

Examples

Good category plan

Development, Design, SEO, Hosting. Each represents a broad editorial area.

Bad category plan

SEO, SEO Tips, SEO Guide, SEO Guides, Search Engine Optimization Tips. The structure becomes fragmented.

Custom taxonomy

A movie site could use Genre with terms such as Drama, Comedy, and Documentary.

Remember: Taxonomy should reflect how people and the website need to organize content, not every keyword variation you can think of.

Themes

Understand what the theme owns, what a child theme is, how templates work, and why changing a theme can change the site experience.

Theme responsibility
Theme
→
Templates
Layout
Typography
Styling
Presentation

A theme controls how WordPress content is presented. It does not own all website data or every feature. A well-structured site keeps presentation and functionality separated as much as practical.

Important sub-concepts

Parent theme

The main theme that provides the base templates, styling, and theme functionality.

Child theme

A separate theme that inherits from the parent and gives you a safer place for code-level theme customizations.

Template

A rule or file that decides how a type of content is rendered, such as a single post, archive, page, header, or footer.

Theme-specific features

Some themes add options, blocks, widgets, shortcodes, or custom behavior. These can create dependency on that theme.

Examples

Same content, new look

A service page can keep the same title and content while a new theme changes typography, spacing, header, footer, and layout.

Child theme use

You need a custom PHP template change. Put it in a child theme so a parent theme update does not overwrite it.

Theme switch risk

If the old theme provided special widgets or shortcodes, changing themes can affect how those elements display.

Remember: Content and presentation are connected, but they are not the same thing. A theme is primarily the presentation layer.

Plugins

Learn what plugins do, where they fit, why dependencies matter, and why plugin quality matters more than a magic plugin count.

Custom Features

A plugin is code that extends or changes WordPress functionality without editing WordPress Core. Plugins use WordPress APIs and hooks to add features.

Important sub-concepts

Hooks

WordPress exposes actions and filters so plugins can run code or modify data at defined points without changing Core files.

Dependencies

An add-on may require a parent plugin. If the dependency is missing or disabled, the add-on may stop working.

Overlap

Two plugins may try to solve the same problem, create duplicate features, or conflict with each other.

Maintenance

Every plugin adds code you must keep compatible, secure, updated, and understood.

Examples

Form plugin

Adds fields, validation, emails, submissions, spam protection, and integrations.

SEO plugin

Adds SEO titles, meta descriptions, XML sitemaps, schema settings, and search-related controls.

Custom plugin

A developer can build a plugin for an exact workflow, API integration, custom content type, automation, or admin feature.

Remember: "Too many plugins" is not a fixed number. Judge quality, overlap, performance, support, security, and necessity.

WordPress Users and Roles

Understand the standard roles and the principle of giving each person only the access needed for their work.

Role permission pyramid
Administrator
Editor
Author
Contributor
Subscriber
What each role means

Administrator

Broad site administration. Can manage major settings, users, themes, plugins, and content on a standard single-site install.

Editor

Manages and publishes content across the site without needing full site administration.

Author

Can create, publish, and manage their own posts.

Contributor

Can write and manage their own posts but cannot normally publish them directly.

Subscriber

Has minimal access, mainly to their own profile and subscriber-level features.

Capabilities

Roles are collections of capabilities. Developers can create custom roles or adjust capabilities when a project needs more precise access.

Examples

Content manager

Editor may be enough. Administrator is unnecessary if the person does not manage plugins, themes, users, or site settings.

Guest writer

Contributor can prepare content for review without publishing it.

Common mistake

Giving Administrator access to everyone increases accidental-change and security risk.

Remember: Use least privilege. Give the minimum access required for the task.

Permalinks and URLs

Understand slugs, URL structure, and why live URL changes should be treated as migrations rather than casual edits.

URL anatomy
https://scheme

A permalink is the permanent URL used to access a piece of content. The slug is usually the human-readable final part that identifies that page or post.

Why URL stability matters

Once a URL is live, it may be linked from menus, other pages, search engines, emails, ads, social posts, bookmarks, analytics reports, or external websites. Changing it without a plan can send those references to a missing page.

Planned URL change
Old URL
→
301 Redirect
→
New URL
Examples

Clean slug

/services/wordpress-development/ clearly describes the page.

Risky edit

Changing a ranking page from /wordpress-development/ to /wp-dev/ without redirects can break old links.

Planned migration

Update the URL once, create the correct redirect, update internal links, and verify the destination works.

Remember: A live URL is part of the website's public structure. Do not change it casually.

What actually happens

The physical media file normally goes into wp-content/uploads. WordPress also creates an attachment record in the database and stores metadata about that media. Depending on configuration, WordPress can generate multiple image sizes.

ALT text

Describes the meaningful purpose of an informative image for accessibility. It should be useful, not stuffed with unrelated keywords.

Title and caption

These have different display and editorial purposes. They are not replacements for correct ALT text.

File preparation

Use sensible dimensions, compression, format, and filename before uploading when possible.

Duplicate assets

Uploading the same image many times creates clutter and unnecessary storage. Reuse the existing suitable asset when appropriate.

Examples

Team photo

Upload an optimized version once and use meaningful ALT text that reflects the image context.

Decorative shape

If an image is purely decorative and adds no information, accessibility handling may differ from an informative image.

Common mistake

Uploading a 6000px camera image directly for a small 500px content area wastes bandwidth and storage.

Remember: The Media Library is not just a file dump. Treat media as reusable, organized website assets.

What gets updated

WordPress Core

The main platform receives maintenance, security, compatibility, feature, and major-version updates.

Themes

Themes receive bug fixes, feature changes, compatibility work, and security updates.

Plugins

Plugins receive feature, bug, security, and compatibility updates. Some updates can change database or configuration behavior.

Environment

PHP versions, server software, caches, integrations, and custom code can affect compatibility even though they are not WordPress update buttons.

What to test

Front end

Check homepage, key templates, navigation, responsive layout, and important interactive elements.

Functional paths

Test forms, logins, checkout, search, filters, integrations, and other business-critical workflows.

Admin

Check editing, saving, media, plugin screens, and workflows used by the team.

Remember: Updates are necessary, but clicking Update without backup and verification is not a professional production process.

WordPress File Structure

Learn the purpose of wp-admin, wp-content, wp-includes, and the main site-specific folders without memorizing every file.

Folder tree
WordPress Root
wp-admin
wp-content

What each area means

wp-admin

Contains WordPress Core files used for the administration system. Treat it as Core, not a custom-code location.

wp-includes

Contains WordPress Core libraries, APIs, classes, functions, and internal code. Do not use it as a customization folder.

wp-content

The main area for site-specific themes, plugins, uploads, and other content-related folders created by software.

wp-config.php

A root configuration file that connects WordPress to important environment settings such as the database. Handle it carefully.

Examples

Custom theme file

Belongs in the appropriate theme or child theme under wp-content/themes.

Custom plugin

Belongs under wp-content/plugins, not inside Core folders.

Unsafe location

Adding custom business logic directly to wp-includes can be overwritten by a Core update.

Remember: Core folders belong to WordPress. Site-specific code should live in the proper extension layer.

WordPress Database Basics

Understand what WordPress stores in the database and how content, metadata, users, settings, and taxonomies are related without writing SQL yet.

Content to database
WordPress Database
Posts / Pages
Post Meta
Users
User Meta
Options
Terms
Comments

You do not need SQL yet. The goal is to understand that WordPress content is structured data, not just text sitting inside an HTML file.

Key ideas

Posts and Pages

Both are stored as content records. WordPress distinguishes their content type and uses that information to treat them differently.

Metadata

Extra key-value information can be attached to content or users. Custom fields are a common example of metadata.

Options

Site and plugin settings can be stored as options. This is different from content records.

Taxonomy relationships

WordPress stores terms and the relationships that connect those terms to content.

Examples

Service page

The title and body are content. A custom "starting price" field can be metadata attached to that page.

User profile

The account is a user record. Additional profile information can be stored as user metadata.

Media upload

The physical image file lives in uploads, while WordPress stores an attachment record and related metadata in the database.

Remember: A WordPress website is both files and database data. A complete backup strategy must understand both.

WordPress Core vs Customization

Learn the boundary between WordPress Core and your custom work so updates remain safe and maintainable.

Safe vs unsafe customization

Safe direction

Core stays untouched. Use child themes, plugins, custom plugins, hooks, APIs, blocks, and supported extension points.

Unsafe direction

Edit WordPress Core files directly to add project-specific functionality. A future Core update can overwrite those changes.

Think in extension layers
Your Custom Plugin / Child Theme / Integration
Theme and Plugins
WordPress APIs and Hooks
WordPress Core
Database + Server Environment
Examples

Custom feature

Build a custom plugin that registers the feature and uses WordPress hooks and APIs.

Theme template change

Use a child theme or supported theme customization layer when code-level theme changes are needed.

Direct Core edit

Changing a file inside wp-admin or wp-includes to make a client feature work creates an update and maintenance problem.

Remember: Professional WordPress development extends Core. It does not hack Core.
